# Three Vaults as Working Memory

Back to [[00 SDLC Home]].

| Layer | Question | Size | How it changes | Readers |
|---|---|---|---|---|
| `spec/` | *What* are we building, and why? | 146 notes · 138,283 words · 4,714 wikilinks | Written once (iteration 00), then extended by dated appendices and open questions | the AI before any change to the domain; the owner; future contributors |
| `adr/` | *How* do we build it, and what did we decide? | 23 records · 8,277 words | 1 to 17 new records per iteration; old ones amended, never rewritten | the AI before any change of structure; reviewers |
| `meta/` | *How* are we working, and what did we learn? | 20 notes · 9,171 words | Every iteration: a note, observations and register updates | the AI at the start of a session; the owner; researchers of the method |
| Generated | What shape is the code? | `TOPOLOGY.md` | Regenerated by the checker; the check fails if it is stale | everyone |
| Public face | What is this? | `README.md` and screenshots | Every iteration that matters to the public | visitors on GitHub |
| Private memory | What must the AI not forget? | 2 notes outside the repository | Rarely | the AI only |

## Why three and not one
- **Different rates of change.** The spec should be stable; decisions accumulate; process notes grow every day. Mixing them would make the spec churn and bury the decisions.
- **Different kinds of truth:**
  - the spec states intent, even where the code differs;
  - ADRs state what was chosen and why, including departures from the spec;
  - meta states what happened, including the mistakes.
- **Licences can differ.** Today all three vaults are CC BY-NC 4.0 and the code is Apache 2.0 (`adr/records/ADR-0019`).

## How the AI actually uses them
- **Before touching a domain rule,** it reads the relevant spec note and `Canonical Parameters`. The approval limit, the safety delay and the event names all came from there.
- **Before changing structure,** it reads the gates (17 files) rather than the code (285 files), and the ADR that set the rule.
- **After an iteration,** it writes back: the iteration note, observations, registers, ADRs, spec appendices, the README and TOPOLOGY.

## Observation
By volume, the documentation (about 155,000 words) is the primary artefact and the code (11,701 lines) is secondary. That is unusual for software, and characteristic of this method: **the vaults are the program that directs the programmer.**
